# Motion and interaction follow-up — November 4, 2026

The working-tree native C++ candidate now shares animated panel geometry with pointer input, uses finite retargetable focus motion, and coalesces rapid artwork changes. The fourth-column right-leaning 4/3/2 staircase, five compact bottom cards, collection keyboard and exact return identifiers are preserved.

## Behavior

- **Focus:** a 140 ms ease-out track starts at the displayed rectangle when retargeted. Identical targets keep their progress. The endpoint snaps exactly, requests its final frame, then becomes idle. The same focus track is painted on Home, panels, Control Center, catalog, keyboard and inspector. The selected control responds immediately while the ring moves.
- **Panel entry:** general panels, Control Center and inspector use one 200 ms presentation with at most 12 logical pixels of translation. Cards, icons, focus framing and hit bounds use the same offset. Catalog and keyboard geometry stay untranslated. Pointer input is mapped back through the actual presentation pose; no animation lock was added.
- **Artwork:** each segment lasts 300 ms. New focus changes preserve the displayed source/target pair and its progress, replacing only one pending target. Requesting the current destination cancels the pending target. Excess elapsed time carries into the queued segment. Reduced motion resolves the latest target immediately. Completed artwork retains and draws one image.
- **Lifecycle:** all presentation tracks freeze while inactive. The first restored frame consumes zero hidden elapsed time; subsequent updates resume. Dwell is reset. Reduced motion resolves focus, panel and artwork state on the next update.
- **Invalidation:** finite focus movement requests redraw through its exact endpoint. Moving within the already-focused pointer target updates interaction activity without forcing a redraw. Other service/content invalidation remains as before.

This slice does not implement exit choreography, animated inspector content stepping, prior-tile scale release, metrics-only text, glyph atlases, renderer batching, new artwork, shader precision changes or a new clock deadline. These remain in the earlier [4K/240 synthesis](../.ai/runs/20261104-4k240-reviews/4K240-SYNTHESIS.md).

## Deterministic native QA

`--step-ms N` selects a finite positive animation step up to 50 ms. It requires a bounded desktop `--frames` run and is rejected for webOS. The default application clock still uses elapsed wall time. Reports explicitly label `fixed-step-desktop-qa`; software animation steps are not actual refresh or throughput measurements.

Desktop input scripts can request `trace`. Up to 256 motion samples are retained in memory and written in the final report. No trace files are written during interaction. Reports include logical and presented focus targets, focus settlement, panel progress/offset and artwork source/target/pending state.

`tests/native_motion_qa.py` checks painted-edge activation, rejection of unpainted resting bounds, Control Center cards, inspector Back, exact focus settlement, rapid artwork coalescing/cancellation, inactive/resume behavior, reduced motion, 60/120/240 step equivalence, 720p/2160p mapping, odd sizes, vertical/horizontal letterboxes and bars, rapid reversal, and catalog/keyboard/inspector/launcher return poses.

The preserved pre-fix executable includes additive fixed-step/trace observability but retains the original motion behavior. With the final 33-check driver it records **13 passed / 20 failed**. The current executable records **33 passed / 0 failed**. Initial baseline artifacts and an incorrect early inspector click coordinate are retained; the expanded baseline uses the corrected left-side Back coordinate and is authoritative.
